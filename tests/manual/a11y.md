# Accessibility Manual QA Checklist

PRD §10.6 + LLD §15 a11y 요구사항을 수동으로 검증한다.
Phase 1 출시 전 한 번, 그리고 UI 변경이 큰 PR마다 재실행한다.

## 환경

- macOS: VoiceOver (Cmd+F5로 토글)
- Windows: NVDA (무료 다운로드)
- 브라우저 무관: 색맹 시뮬레이터 (Chrome devtools → Rendering → Emulate vision deficiencies)
- Obsidian desktop 1.5+

## 1. 키보드 네비게이션

- [ ] Tab/Shift-Tab으로 ProjectSelector → HideCompletedToggle → NewTaskButton → ProjectContextHeader(Open memo → quick memo → Save → memo actions) → 첫 번째 카드 → ... 순으로 도달.
- [ ] focus ring이 모든 interactive element에서 시각적으로 명확 (Obsidian accent color, `--interactive-accent`).
- [ ] focus가 화면 밖으로 나가지 않음 (modal 열렸을 때 modal 안에 trap 안 되어도 OK — Phase 1).
- [ ] Esc로 NewTaskModal, NewProjectModal, ConfirmDialog 모두 닫힘.

## 2. 카드 키보드 단축키 (KanbanCard)

| 키 | 기대 동작 |
| --- | --- |
| Enter | 노트가 새 탭으로 열림 |
| Cmd/Ctrl + Enter | 다음 status로 이동 (todo→doing, doing→done) |
| Cmd/Ctrl + Shift + Enter | 이전 status로 이동 |
| Cmd/Ctrl + E | Archive로 이동 |
| Cmd/Ctrl + Backspace | confirm dialog 후 삭제 |

- [ ] 마우스 미사용으로 위 5개 시나리오 모두 가능.
- [ ] 마지막 status에서 Cmd+Enter는 no-op (이전 status도 첫 status에서 no-op).
- [ ] 카드 focus 상태에서 단축키가 다른 Obsidian 단축키와 충돌하지 않음.
- [ ] 카드 ⋮ 메뉴를 keyboard로 열고 Open note / Edit / Archive / Delete에 도달 가능.
- [ ] Edit task dialog의 Title / Priority / Project label이 screen reader에서 각각 read됨.

## 3. Project quick memo keyboard

- [ ] 특정 project 선택 후 Open memo → New meeting → quick memo textarea → Save → recent memo actions 순서로 Tab 이동.
- [ ] quick memo textarea에서 Cmd/Ctrl+Enter 저장 가능.
- [ ] 저장 후 `role="status"`가 "Saved" 또는 "저장됨"을 announce.
- [ ] recent memo action buttons(Create task, Promote note, Copy link)이 keyboard로 실행 가능.

## 4. ARIA semantics

- [ ] KanbanBoard: `<ul role="list" aria-label="Kanban board">`.
- [ ] StatusVisibilityBar: chip group has `aria-label="Visible statuses"` / `"표시할 상태"`.
- [ ] StatusVisibilityBar chips expose `aria-pressed=true/false`; 마지막 visible status chip은 disabled 또는 no-op.
- [ ] KanbanColumn: `<ul role="list" aria-labelledby="tm-col-title-{id}">`.
- [ ] KanbanCard: `<li role="listitem" aria-label="{title}, status {status}, priority {priority}">`.
- [ ] Drag handle 버튼에 `aria-label="Drag handle"`.
- [ ] ProjectSelector `<select>`에 `aria-label="Project filter"`.
- [ ] ProjectContextHeader `<section>`에 `aria-label="Project memo"`.
- [ ] Quick memo textarea에 `aria-label="Quick memo"`.
- [ ] Quick memo 저장 상태는 `role="status"`로 노출.
- [ ] PriorityBadge에 `aria-label="Priority {Level}"`.
- [ ] Modal: `role="dialog" aria-modal="true" aria-label="..."`.
- [ ] Mobile MoveNext/MovePrev 버튼에 `aria-label="Move to next status (doing)"` 등.

## 5. Screen reader 시나리오

VoiceOver 또는 NVDA로:

- [ ] 보드를 열면 "Kanban board, list" 정도로 announce.
- [ ] 카드를 focus하면 title + status + priority 모두 read.
- [ ] PriorityBadge가 단독 focus 안 받지만 카드 aria-label에 priority 포함되어 있음.
- [ ] NewTaskModal 열면 "New task, dialog" 정도로 announce.
- [ ] EditTaskModal 열면 "Edit task, dialog" 정도로 announce.
- [ ] Project quick memo composer 저장 상태가 변경될 때 screen reader가 상태를 read.
- [ ] modal 안의 input label이 정상 read ("Title", "Status", "Priority").
- [ ] Status visibility chip과 mobile status tab이 서로 다른 label로 announce.
- [ ] Mobile board의 status tabs가 "tab" role로 announce.

## 6. Color blind 검증

Chrome DevTools → Rendering → Emulate vision deficiencies → Protanopia / Deuteranopia / Tritanopia / Achromatopsia.

- [ ] PriorityBadge: 색상이 사라져도 텍스트 라벨로 우선순위 식별 가능 (Low/Medium/High).
- [ ] Drop target hover state: 색상 외에 border 변화로 식별 가능.
- [ ] focus ring: 색상이 흐려져도 outline 있음.
- [ ] Diagnostics kind 색상: 텍스트 라벨이 함께 있음.

## 7. 다크/라이트 테마

- [ ] Obsidian theme 전환 (Settings → Appearance → Base color scheme) 후 보드 재진입 → 카드 색상이 함께 변경.
- [ ] Diagnostics pane도 테마 적응.
- [ ] Modal 배경 overlay가 두 테마에서 모두 보임.

## 8. Mobile (iOS Obsidian, Android Obsidian)

- [ ] ribbon으로 view 열림.
- [ ] Status tab 전환 정상.
- [ ] "다음 status" 버튼 동작 (status 변경 후 카드 사라짐).
- [ ] Long-press 또는 ⋮ 메뉴로 archive/delete 동작.
- [ ] confirm dialog 모바일에서 정상 표시.
- [ ] dnd가 발동되지 않음 (의도적 — ADR-0009).
- [ ] Project quick memo textarea와 Save button이 soft keyboard 상태에서 가려지지 않음.
- [ ] Preview action buttons가 좁은 폭에서 overflow 없이 wrap.
