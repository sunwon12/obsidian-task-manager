# ADR-0013: 단계는 인간·AI 시간을 구분하는 측정 국면으로 둔다

## Date

2026-08-27

## Context

[ADR-0012](./0012-ai-draft-suggestions.md)는 단계를 AI 위임 라우팅 키로 보고
`[결정]`·`[조사]`·`[실작업]`·`[검증]`·`[대기]` 다섯 종류, 3~7개, 첫 단계 제한과 상세 산출물
이름을 정했다.

실제 Ratko 사용에서 단계의 목적은 달랐다. 사용자는 `stepSeconds`로 **AI를 돌린 시간과 직접
생각·판단한 시간을 분리**해 생산성을 보려 했고, 패널에서는 현재 어느 국면인지 빠르게 알아야 했다.
상세한 단계명은 작업 지시를 중복하고 입력 비용과 시각적 잡음만 늘렸다.

## Decision

- 실행 주체 접두어는 `[인간]`과 `[AI]` 두 개만 새로 생성한다.
- 단계명은 `[인간] 설계`, `[AI] 구현`, `[인간] 검증`처럼 짧은 국면명으로 쓴다.
- 실행 주체가 바뀌거나 사용자가 시간을 따로 보고 싶은 큰 국면이 바뀔 때만 나눈다.
- 최소 단계 수, 첫 단계 종류, 결정 단계 유무를 강제하지 않는다.
- 방법·산출물·완료 조건은 카드 본문, 설계 문서, 실행 스킬이 소유한다.
- 대기 시간은 인간·AI 생산성 시간이 아니므로 단계 대신 HOLD 상태나 비고로 관리한다.
- 기존 단계는 자동 변환하지 않는다. 과거 `stepSeconds`의 의미를 바꾸지 않도록 사용자가 편집할 때만
  새 접두어로 정리한다.
- `steps: string[]`과 인덱스 기반 시간 저장 구조는 유지한다. 편집·재정렬 시 누적 시간과 현재 단계
  포인터를 함께 보존한다.

AI 초안은 빈 카드에 이 기준의 짧은 국면만 제안한다. 이미 단계가 있으면 기존대로 덮어쓰지 않고,
실행 주체 누락·과도한 상세도·측정할 국면 전환 누락만 비평한다.

## Alternatives Considered

| 옵션 | 장점 | 단점 | 탈락 사유 |
| --- | --- | --- | --- |
| A. 다섯 작업 종류를 유지하고 인간·AI 속성을 추가 | 작업 종류와 주체를 모두 분석할 수 있음 | 입력·표시·집계 축이 늘고 현재 국면을 한눈에 보기 어려움 | 지금 측정하려는 질문은 작업 종류가 아니라 인간 시간 대 AI 시간이다 |
| B. 상세 단계명을 유지 | 단계 자체가 실행 지시서가 됨 | 본문·설계·스킬과 중복되고 입력 비용이 커짐 | 단계의 소유 책임은 지시가 아니라 측정이다 |
| C. 구조화 객체로 즉시 마이그레이션 | owner를 타입으로 강제할 수 있음 | 기존 Markdown·타이머 인덱스·Swift 앱까지 마이그레이션 필요 | 접두어만으로 현재 목적을 충족하며 마이그레이션 위험이 불필요하다 |

## Consequences

- **긍정적**: 접두어별 누적 시간으로 인간 사고 시간과 AI 실행 시간을 분리할 수 있고, 좁은 Ratko
  패널에서도 현재 국면이 짧게 보인다. 단계 입력 비용이 낮아진다.
- **부정적**: `조사`·`구현` 같은 작업 종류별 통계는 접두어만으로 안정적으로 집계할 수 없다.
- **리스크**: 자유 문자열이라 접두어 누락이 가능하다. 완화 — AI 초안과 입력 placeholder가 두 접두어를
  안내하고, 검사기는 누락을 경고하되 기존 데이터를 자동 수정하지 않는다.
- **검증**: 파서가 `[인간]`·`[AI]`를 읽고 이전 접두어를 미분류로 보며, 단일 단계와 임의의 첫 단계를
  허용하는지 단위 테스트한다. AI 프롬프트에 상세 체크리스트 금지와 고정 개수 없음이 포함되는지 확인한다.
