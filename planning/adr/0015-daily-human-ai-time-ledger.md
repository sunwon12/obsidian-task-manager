# ADR-0015: 인간 구간 원장과 transcript 재계산으로 일일 시간을 확정한다

## Date

2026-08-29

## Context

[ADR-0013](./0013-human-ai-measurement-steps.md)은 카드의 `[인간]`·`[AI]` 단계를 생산성 측정 국면으로
정했다. 실시간 `AI 세션 점검`은 Codex·Claude transcript에서 AI 실행 시간을 계산하지만,
현재 열린 프로세스만 대상이고 결과를 저장하지 않았다. `stepSeconds`는 단계별 전체 누적값이라
하루 경계를 지난 뒤에 인간 시간을 복원할 수도 없었다.

## Decision

- 랏코 타이머가 `[인간]` 단계에서 실행될 때 시작·종료 시각을 `TaskMaster/Metrics/human-timer-ledger.json`에
  구간으로 저장한다. 단계 전환·일시정지·완료·외부 상태 변경과 앱 재실행에서 활성 구간을
  조정한다.
- 매일 00:10 전날을 확정한다. 앱이 꺼져 있었으면 다음 실행 시 빈 날짜를 찾아 보정하고,
  첫 실행은 최근 30일을 백필한다.
- Codex는 기본 `~/.codex/sessions`와 Orca runtime home의 `sessions`를 함께 읽는다. Claude는 사용자가
  security-scoped bookmark로 연결한 프로젝트만 읽고, 연결 개수를 커버리지로 남긴다.
- Codex의 `task_complete.duration_ms`는 런타임 실측값을 쓰고, 날짜 경계를 가로지르면 턴의 벽시계
  구간 비율로 나눈다. Claude는 `user`에서 마지막 `assistant`까지의 이벤트 시각 차를 계측한다.
- 대화형 AI·헤드리스 자동화·서브에이전트 시간을 별도 필드로 저장한다. 자동화와 자식 시간을
  사용자의 대화형 AI 시간에 합산하지 않으며, 응답 대기도 생산성 시간에서 제외한다.
- 기계 정본은 `human-ai-daily.json`, 사람·AI가 읽는 롤업은 `human-ai-daily.md`로 분리한다.
  동일 날짜 재실행은 append가 아니라 교체로 멱등하게 처리한다.
- 같은 Codex 턴이 부모·자식 transcript에 재수록될 수 있으므로 세션·시작·종료·실측 시간의 동일성을
  기준으로 중복을 제거한다. 여러 세션의 실행량은 합산하므로 일일 AI 합계는 24시간을 넘을 수 있다.

## Alternatives Considered

| 옵션 | 장점 | 단점 | 탈락 사유 |
| --- | --- | --- | --- |
| A. 매일 `stepSeconds` 스냅샷의 차이 | 구현이 작음 | 앱이 며칠 꺼지면 날짜별 분할 불가, 완료·삭제 카드 누락 | 밀린 배치를 정확히 보정할 수 없다 |
| B. AI 시간을 세션 점검 결과에서 스냅샷 | 기존 코드 재사용 | 이미 종료된 프로세스와 누락된 파일 이벤트를 잃음 | 일일 확정치가 아니다 |
| C. 외부 DB에 세션 이벤트 저장 | 질의·시각화가 쉬움 | 평문 vault 정본·로컬 개인정보 계약과 충돌 | 현재 규모에 불필요하다 |

## Consequences

- 타이머를 `[인간]` 단계에서 실제로 실행한 시간만 인간 집계에 들어간다. 이 기능 배포 전의
  과거 인간 시간은 날짜 경계 근거가 없어 백필하지 않는다.
- transcript를 외부 모델에 보내지 않고 로컬에서만 파싱한다. 첫 30일 백필은 일시적으로 디스크 I/O를
  쓰지만 메인 스레드 밖에서 실행한다. 파일은 줄 단위로 읽고 수정 시각·크기별 파싱 캐시를 유지한다.
- Claude 로그를 연결하지 않은 날은 0으로 숨기지 않고 커버리지 미연결을 표시한다.
- 랏코 패널에서 최신 확정치·집계 중·실패·전체 기록 진입을 보여준다.
