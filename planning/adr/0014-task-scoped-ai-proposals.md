# ADR-0014: 태스크 AI는 읽기 전용 문맥과 확인형 변경안을 쓴다

## Date

2026-08-27

## Context

Swift Ratko에는 일일 피드백과 수동 단계 편집은 있지만, 각 태스크를 문맥으로 질문하거나 AI 단계 초안을
받을 진입점이 없었다. 일반 대화창을 따로 열면 사용자가 태스크 제목·본문·현재 단계를 다시 설명해야 하고,
AI가 Markdown을 직접 고치게 하면 실행 중 타이머와 외부 수정 충돌을 우회한다.

## Decision

- 모든 집중·다음 할 일·포커스 창 카드에서 태스크 id로 구분되는 AI 창을 연다.
- 프롬프트에 최신 제목·본문·단계·현재 단계와 해당 창의 최근 대화를 넣는다.
- Claude에는 `Read,Grep,Glob`만 허용하고 파일 쓰기 권한을 주지 않는다.
- 응답은 `reply`, `steps`, `memo`, `body` JSON 제안으로 제한한다.
- 질문 답변은 바로 표시하되, 변경은 적용·버리기 UI를 거쳐 사용자가 확인한 뒤 `TaskMarkdownRepository`가
  쓴다.
- 제안 기준 `updatedAt`과 최신 태스크가 다르면 적용을 거부한다.
- 단계 제안은 [ADR-0013](./0013-human-ai-measurement-steps.md)의 `[인간]`·`[AI]` 짧은 국면만 받는다.
  교체 시 동일 문자열을 우선 매칭하고 이름만 바뀐 항목은 남은 index 순서로 연결해 누적 시간과 현재
  단계 포인터를 보존한다.

## Alternatives Considered

| 옵션 | 장점 | 단점 | 탈락 사유 |
| --- | --- | --- | --- |
| A. 터미널에서 interactive Claude 열기 | 구현이 단순하고 자유도가 높음 | 태스크 변경 적용·충돌·타이머 보존을 랏코가 통제할 수 없음 | 태스크 UX와 데이터 계약이 분리된다 |
| B. `acceptEdits`로 카드 파일 직접 수정 | 대화 한 번으로 즉시 반영 | `updatedAt` 충돌과 단계 시간 매핑을 우회함 | AI가 파일 writer가 되면 기존 저장소 계약이 깨진다 |
| C. 답변만 제공하고 변경 기능은 제외 | 안전하고 단순함 | 단계 채우기·메모·본문 수정 요구를 충족하지 못함 | 사용자가 AI 답을 다시 손으로 옮겨야 한다 |

## Consequences

- **긍정적**: 어떤 카드에서 열어도 AI가 그 태스크를 알고 시작하며, 대화와 실제 변경이 한 창에서
  이어진다. 모든 쓰기는 기존 Markdown 저장소와 타이머 계약을 탄다.
- **부정적**: 각 메시지가 독립 `claude -p` 실행이라 응답마다 시간이 들고, 앱 재실행 뒤 대화 이력은
  복원하지 않는다.
- **리스크**: AI가 잘못된 JSON이나 주체 없는 단계를 반환할 수 있다. 완화 — 파서가 응답을 검증하고
  실패 사유·재시도를 창 안에 남기며, 변경은 사용자가 적용하기 전까지 디스크에 닿지 않는다.
- **검증**: Claude envelope 파싱, 주체 없는 단계 거부, 태스크 문맥 프롬프트, 단계 rename·reorder 시간
  매핑을 단위 테스트한다. macOS 13 타깃 debug/release build와 설치본 실행을 확인한다.
