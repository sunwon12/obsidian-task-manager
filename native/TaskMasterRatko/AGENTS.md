# TaskMaster Ratko 개발 규칙

이 파일은 저장소 상위 지침을 상속하며, `native/TaskMasterRatko/` 아래 Swift 앱에 다음 규칙을 추가한다.

## 사용자 요구는 UX가 완결된 상호작용으로 구현한다

- 사용자가 말한 기능만 화면에 노출하고 끝내지 않는다. 그 기능에 들어가는 방법, 성공·실패 피드백,
  저장, 취소, 포커스 이탈, 바깥 클릭, `Esc`, 창 닫기와 재실행까지 일반적인 macOS 사용 흐름을 함께
  설계한다.
- 편집·선택·드래그 같은 임시 모드는 사용자를 가두지 않는다. 다른 곳을 클릭하면 종료하고, 유효한
  변경은 안전하게 저장한다. 명시적 취소는 저장하지 않으며 원래 값을 보존한다.
- 요구사항의 글자 그대로와 사용자가 실제로 하려는 일을 함께 검증한다. 좁은 메뉴바 패널에서도
  조작법이 발견 가능해야 하고, 클릭 결과와 현재 상태가 즉시 보여야 한다.
- 문구나 순서를 바꾸는 UI는 타이머·선택·누적 시간처럼 사용자가 유지되리라 기대하는 상태를 보존한다.
  파괴적이거나 되돌리기 어려운 동작은 별도 확인 없이 추론해 실행하지 않는다.
- 태스크 드래그는 작은 아이콘 하나에 의존하지 않는다. 제목 열기·재생/정지·단계 선택/수정·입력·AI·메모처럼
  클릭을 소유한 컨트롤은 그대로 두고, 상태·시간·여백을 포함한 카드의 나머지 비조작 영역 전체를 드래그
  시작점으로 쓴다. 같은 목록의 정렬과 목록 사이 이동을 모두 지원하고, 목록을 넘겨 상태가 바뀌어도 누적
  타이머와 단계 시간은 보존하며, 정렬 결과는 앱 재실행 뒤에도 복원한다.
- 드래그 정렬 목록이 화면보다 길면 포인터가 스크롤 영역 위·아래 가장자리에 머무는 동안 자동으로
  스크롤한다. 카드 사이 진입·이탈에서는 끊기지 않아야 하고, 중앙 복귀·드롭·취소·패널 닫기에는 즉시
  멈춰 백그라운드 스크롤이 남지 않게 한다.
- 드래그 중에는 놓았을 때 들어갈 카드 사이 위치를 삽입선으로 미리 보여준다. 삽입선은 포인터를 따라
  한 곳에만 존재하고, 정상 드롭 콜백 여부와 무관하게 실제 `leftMouseUp` 이벤트에서 즉시 제거한다.
  `pressedMouseButtons` 폴링은 AppKit 드래그 중에도 0을 반환할 수 있으므로 종료 판정에 쓰지 않는다.
- 작업량에 따라 내용 길이가 달라지는 패널은 사용자가 크기를 조절할 수 있게 하고, 조절 손잡이를
  발견 가능하게 드러낸다. 저장한 크기는 재실행에도 복원하되 현재 화면의 사용 가능 영역을 넘지 않는다.
- 완료 전에 정상 경로만 보지 않는다. 최소한 진입 → 수정 → 저장, 취소, 바깥 클릭, 빈 값·오류,
  라이브 갱신 중 상태 보존을 확인하고 관련 계약 테스트를 남긴다.

## 단계는 인간·AI 시간을 구분하는 측정 국면이다

- 단계는 세부 체크리스트나 AI 작업 지시서가 아니다. 인간이 생각·설계·판단한 시간과 AI가 실행된
  시간을 나눠 재기 위한 관측 단위이자, 지금 어느 국면인지 알아차리는 짧은 표지다.
- 단계명은 `[인간] 설계`, `[AI] 구현`, `[인간] 검증`처럼 실행 주체와 짧은 국면만 쓴다.
  `설계를 어떻게 할지 정리`처럼 방법·산출물·세부 절차를 단계명에 넣지 않는다.
- 실행 주체가 바뀌거나 사용자가 시간을 따로 보고 싶은 큰 국면이 바뀔 때만 단계를 나눈다.
  단계 개수, 첫 단계 종류, 상세도에 획일적인 규칙을 강제하지 않는다.
- 상세 작업 계약은 카드 본문·설계 문서·스킬이 소유한다. 단계 편집·재정렬 때는 해당 국면에 이미
  쌓인 `stepSeconds`와 현재 단계 포인터를 그대로 보존한다.

## 태스크 AI는 문맥을 알되 직접 쓰지 않는다

- 모든 태스크 AI 진입점은 선택한 태스크의 id·제목·본문·단계·현재 국면을 문맥으로 고정한다. 다른
  태스크의 대화나 변경안을 섞지 않는다.
- 모델에는 vault 읽기 도구만 허용한다. 단계·본문·메모 변경은 JSON 제안으로 받고 사용자가 변경안을
  확인해 적용한 뒤에만 랏코 저장소가 파일을 쓴다.
- 제안 생성 뒤 태스크가 외부에서 바뀌었으면 적용하지 않고 최신 내용으로 다시 요청하게 한다.
  적용·버리기·실패·재시도 상태가 창 안에서 보여야 하며, 미확정 변경안이 있으면 다음 대화를 막는다.
- AI 단계 교체도 일반 편집과 같은 타이머 계약을 따른다. 동일 단계와 이름만 바뀐 국면의 누적 시간,
  실행 중 현재 단계, 재정렬된 포인터를 보존하고 새 국면만 0초로 시작한다.
