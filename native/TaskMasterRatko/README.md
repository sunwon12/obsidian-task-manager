# TaskMaster Ratko

Obsidian/Electron과 별도 프로세스로 실행되는 macOS 메뉴바 앱이다. SwiftUI가
`TaskMaster/Tasks/*.md`와 `TaskMaster/.timers.json`을 직접 읽고 쓴다.

## 소유권

- Swift 랏코: 메뉴바·빠른 패널·타이머·단계 시간·메모·Task 파일 상태 변경
- Obsidian 플러그인: Kanban 보드·Jira·미팅·프로젝트·AI 기능
- 공유 정본: Markdown Task 파일. 타이머 정본은 Swift 랏코만 쓴다.
- 표시 순서: `.board.json`의 `ratkoOrder`. Swift가 쓰고 Obsidian은 drift를 정리하며 보존한다.

플러그인이 열려 있으면 vault 파일 변경 이벤트로 Swift 앱의 수정을 즉시 반영한다.
플러그인이 닫혀 있어도 랏코는 독립적으로 동작한다.

앱을 시작할 때마다 macOS가 저장한 Wi-Fi 상태 아이템 위치를 읽고 랏코의
`NSStatusItem Preferred Position Item-0`을 바로 왼쪽 값으로 다시 기록한다. 따라서
다른 메뉴바 앱이 많아져도 랏코는 Wi-Fi 옆의 항상 보이는 영역을 우선한다.
같은 시점에 `NSStatusItem VisibleCC Item-0`도 켜서 Control Center가 이전 실행의 숨김 값을
남겨 두었더라도 유일한 메뉴바 항목이 제거되며 앱까지 종료되는 일을 막는다.
설치기는 macOS 26의 중첩 `trackedApplications`도 확인한다. 랏코 자체 허용값은 켠 채 다른 앱이
랏코의 `menuItemLocations`를 잘못 소유한 교차 참조만 제거하고, 수정 전 원본을 `/tmp`에 백업한 뒤
`cfprefsd`와 Control Center를 재시작한다. 전체 메뉴바 설정이나 다른 앱의 허용값은 초기화하지 않는다.
메뉴바·패널 헤더·포커스 창은 기존 Electron 버전에서 사용하던 `src/assets`의 랏코
PNG를 앱 번들에 복사해 그대로 사용하며, 일반 수달 이모지로 대체하지 않는다.
메뉴바 자산은 14pt로 그린다. 랏코는 사각형을 꽉 채운 컬러 이미지라 18pt에서도
선형 아이콘인 Wi-Fi보다 크게 보여, 픽셀 크기보다 체감 크기를 맞추는 값을 쓴다.
같은 원본으로 정식 `.icns`를 만들어 앱 번들 아이콘으로 지정하므로 Finder·시스템 설정·알림에도
macOS 기본 플레이스홀더 대신 랏코 얼굴이 표시된다.

패널의 AI 피드백은 기존 `02_일상/03_성찰/일일-일정-피드백.md` 최신 섹션을 읽는다.
접힌 상태에는 오늘의 하이라이트, 펼친 상태에는 스냅샷·불릿 전체를 보여준다.
`피드백 받기`는 기존 `/daily-schedule-feedback` 스킬을 같은 vault에서 실행한다. 08:40
자동 실행은 Obsidian 플러그인이 계속 소유하고 Swift는 수동 실행만 제공해 중복을 막는다.

집중 카드의 기존 단계 문구나 연필 아이콘을 누르면 그 자리에서 수정한다. Enter 또는
체크로 저장하며, 다른 곳을 클릭하거나 패널을 닫아도 유효한 값은 저장하고 편집을 끝낸다.
`Esc` 또는 ×는 저장하지 않고 취소한다. 문구만 바꾸므로 현재 단계와 단계별 누적 시간은 보존된다.

태스크별 `AI 단계 채우기`와 `AI와 대화`는 태스크 id로 구분한 별도 창을 연다. 랏코는
`LSUIElement` 메뉴바 앱이므로 SwiftUI `openWindow` 호출만으로는 새 창이 다른 앱 뒤에 생길 수 있다.
따라서 각 AI 창을 태스크 id로 식별하고 진입할 때 해당 창을 명시적으로 활성화해 전면에 올린다.

`AI 세션 점검`은 주기적으로 폴링하지 않는다. 사용자가 버튼을 누르면 현재 TTY에 연결된
Claude Code·Codex 프로세스를 찾고 로컬 transcript를 읽어 한 화면으로 정리한다. Codex는 프로세스가
실제로 열어 둔 main rollout만 연결해 subagent rollout을 제외하고, Claude의 `-p` 실행과 TTY 없는
프로세스도 자동화로 분리한다. TaskMaster 연결은 작업 경로·응답에서 확인한 Jira key가 태스크 본문과
일치할 때만 수행한다.

미연결 세션을 전부 태스크로 만들지는 않는다. transcript에서 실제 사용자 요청을 읽은 세션만 후보가
되고, 수동 점검 한 번에 후보들을 AI가 묶어서 판정한다. 완료까지 관리할 구체적인 작업이면 작업 목적이
드러나는 제목으로 카드를 만들고, 빈 셸·권한 안내·인사·확인 답변·단순 사실 질문·일회성 잡담은 버린다.
AI에는 전체 transcript가 아니라 최초 요청과 최근 진행 요약만 전달한다. transcript를 읽지 못해 cwd만
아는 Claude 세션도 카드로 만들지 않는다.

`launchd 자동화`는 `~/Library/LaunchAgents/*.plist`만 읽어 사용자가 설치한 자동화의 현재 상태를
보여준다. 시스템의 수백 개 Apple 서비스는 기본 목록에서 제외한다. 실행 중·예약 대기·마지막 실행 실패·
KeepAlive 재시도·plist만 남은 미등록 상태를 구분하고, 실행 주기·PID·실행 횟수·마지막 종료 상태와
명령을 함께 표시한다. 목록 제목은 `Confluence 쿠키 프록시`처럼 용도를 설명하는 한글 이름을 쓰고,
launchctl과 스크립트가 참조하는 실제 Label은 아래 보조 정보로 보존한다. 상세 행에서 plist와 실제 존재하는 stdout·stderr 로그를 열 수 있다. 점검 화면은
읽기 전용이며 잡을 시작하거나 중지하지 않는다.

앱이 실행 중일 때는 Codex 세션 폴더와 사용자가 연결한 Claude 프로젝트 폴더를 macOS 파일 이벤트로
감시한다. 로그 파일이 실제로 바뀐 경우에만 로컬 점검을 한 번 실행하고, 대화형 세션이
`내 응답·검증 대기`로 처음 전환되거나 같은 세션의 완료 시각이 앞으로 간 경우 macOS 알림을 보낸다.
앱 시작 직후의 첫 점검은 기준선만 만들기 때문에 이미 기다리던 세션 알림이 한꺼번에 뜨지 않고,
세션이 잠시 목록에서 사라졌다 돌아와도 같은 완료 건은 다시 알리지 않는다. 알림을 누르면 앱을
활성화하고 AI 세션 점검 창을 전면에 연다. 백그라운드 알림 점검은 카드 생성·상태 변경을 하지 않으며,
미연결 카드 자동 생성은 사용자가 직접 점검 창을 연 흐름에서만 수행한다. 진행·대기 시간과 알림 판정은
전부 로컬이라 토큰을 쓰지 않고, 새 카드 후보의 생성 여부와 제목을 정할 때만 AI를 한 번 호출한다.

각 AI 세션 카드를 누르면 Orca가 공개하는 실행 중 터미널 목록을 그 순간에 조회한 뒤,
해당 Claude·Codex가 실행 중인 터미널 탭을 전면으로 전환한다. 우선 cwd를 맞추고 같은 작업
폴더의 터미널이 여러 개면 세션 id·카드 요약과 터미널 출력·마지막 활동 시각을 추가로
대조한다. 한 세션으로 확정할 수 없으면 엉뚱한 탭으로 추측 이동하지 않고 카드에 오류를 보여준다.

시간 소유권은 기존 단계 계약을 바꾸지 않는다. `[AI]`는 transcript의 완료 turn 실행 시간,
`[인간]`은 연결된 TaskMaster의 `[인간]` 단계 타이머 합계다. `조사·구현·테스트·검증`은 `[AI]`
안의 설명용 하위 국면이며 새 소유권 prefix가 아니다. turn 사이의 사람 응답 대기는 별도로 표시하고
양쪽 시간에서 제외한다. 실시간 상태는 로그 변경 이벤트로 갱신하고, 날짜별 생산성 합계는 하루가 끝난 뒤
그날 로그를 다시 계산한 값을 확정본으로 삼는다.

macOS가 다른 개발 도구의 Application Data 접근을 막는 환경에서는 Claude 카드 위에 폴더 연결 안내가
나온다. 앱 번들의 `NSAppDataUsageDescription`은 요청한 순간에만 로컬 Claude 기록을 읽는다는
용도를 macOS 권한 창에 표시한다. 시스템 접근을 허용한 뒤에도 특정 프로젝트가 막히면
`현재 폴더 연결`을 누르면 열린 Claude 프로젝트의 기록 폴더가 차례로 열리고, 프로젝트마다
한 번 선택하면 macOS가 그 폴더에 한정된 읽기 접근을 허용한다. 연결 직후 다시 점검하며 다음 실행부터는
읽기 전용 북마크로 복원한다. 전체 디스크 접근 권한은 필요하지 않다. 연결하지 않아도
Codex와 TaskMaster 기능은 계속 동작하며, 랏코는 로그를 수정하지 않는다.

점검 결과의 대화형 AI 세션이 태스크와 연결되지 않았다면 랏코가 카드를 자동 생성한 뒤
동일 점검 안에서 다시 연결한다. 카드에는 `ratkoAiSessionKey`를 저장해 재점검·재실행 때 중복
생성을 막고, 세션에 Jira key가 있으면 `jiraKey`를 같이 저장해 후속 Jira 동기화가 같은 카드를
갱신하게 한다. AI가 실행 중인 세션은 `DOING`, 응답·검증 대기 세션은 `TODO`로 생성한다.
로그 권한 부족으로 실행 여부를 확정할 수 없어도 `TODO`로 둔다. 기본 단계는 `[AI] 진행`과
`[인간] 검증`이며, 응답 대기 세션은 바로 `[인간] 검증`을 현재 단계로 선택한다.

현재 작업과 다음 할 일은 카드나 행을 5pt 이상 끌면(짧은 일반 클릭은 기존 컨트롤로 전달됨)
같은 목록 안에서 순서를 바꾸거나 다른 목록으로 옮길 수 있다. 다음 할 일을 현재 작업에 놓으면
`DOING`으로 바뀌며 즉시 측정을 시작하고, 현재
작업을 다음 할 일로 내리면 `TODO`로 바뀌며 타이머를 일시정지한다. 내려놓은 카드의 전체 누적
시간과 단계 시간은 `.timers.json`에 남아 다시 올렸을 때 이어지고, 표시 순서는 `.board.json`의
선택 필드 `ratkoOrder.focusTaskIds`·`nextTaskIds`에 저장되어 재실행 뒤에도 복원된다. Obsidian은
보드를 쓰기 직전에 이 Swift 소유 필드를 다시 읽어 실행 중인 랏코의 최신 순서를 덮지 않는다.
카드를 잡고 작업 목록의 위·아래 56pt 가장자리로 가져가면 그 방향으로 자동 스크롤하며, 가장자리에
가까울수록 부드럽게 빨라진다. 메뉴바 패널에서 SwiftUI 기본 드래그 콜백이 누락되는 문제를 피하려고
AppKit 마우스 스트림으로 포인터 세션을 추적한다. 두 목록은 하나의 드롭 표면을 쓰고 포인터가 각 카드의 중간을 지나는 순간 앞·뒤
경계를 바꾸어, 깜빡이거나 목록 끝으로 튀지 않는 한 개의 보라색 삽입선을 놓을 위치에 미리 표시한다. 잡은 카드는
자리를 옮기는 중임을 바로 알 수 있게 반투명해진다. 마우스를
놓으면 드롭 성공 여부와 관계없이 삽입선과 자동 스크롤을 함께 정리한다.

이 Swift 앱의 구현 판단은 같은 폴더의 `AGENTS.md`를 따른다. 사용자 요구를 버튼 하나로만
옮기지 않고 진입·저장·취소·포커스 이탈·바깥 클릭·오류·라이브 갱신까지 UX 계약으로 완결한다.

## 빌드와 설치

```bash
swift test --package-path native/TaskMasterRatko
scripts/install-ratko.sh /absolute/path/to/vault
```

설치 스크립트는 실행 중인 이전 앱을 종료한 뒤 `~/Applications/TaskMasterRatko.app`을
교체하고 완성된 번들을 ad-hoc 서명한 뒤 로그인 LaunchAgent를 만들어 새 바이너리를 실행한다.
번들 서명은 실행 파일 교체 직후 macOS RBS가 POSIX 162로 재실행을 거부하는 일을 막는다. 설치 시 만든
`config.json`에서 피드백 노트 경로·Claude 실행 파일·프롬프트·제한 시간을 바꿀 수 있다.
